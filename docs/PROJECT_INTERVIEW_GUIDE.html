1. Project in One Minute

AI Career Navigator is a single-page career coaching application. A candidate creates an account, uploads or pastes resume text, asks Groq to analyze or generate career material, and keeps the resulting profile data in MongoDB. The React frontend owns the user experience; an Express API owns authentication, authorization, database access, and all calls containing the Groq secret.

Interview summary: “This is a React and TypeScript career coaching app backed by an Express API. Mongoose stores one candidate document per account, passwords are bcrypt-hashed, and a seven-day JWT ties every profile and AI request to the current candidate. Vite proxies the browser’s /api calls to Express. Groq runs server-side and returns structured JSON for resume review, roadmaps, mindmaps, and interview practice.”

2. Architecture and Request Flow

1 · BrowserReact pages, controls, context state
2 · Vite proxy/api/* to port 3001
3 · ExpressValidate request, verify JWT
4 · MongoDBskillquest.candidates
5 · Groq (AI only)Server-side model request

During development, the browser loads from http://localhost:8080. Its relative API requests go to /api; the Vite proxy forwards them to http://127.0.0.1:3001. This makes browser and API calls same-origin from the frontend’s point of view and avoids exposing a second public origin. Express connects to the MongoDB URI from the server environment. AI routes call Groq directly from Node, so the Groq key never enters a JavaScript bundle.

Typical authenticated request

  1. The user submits a form in a page component.
  2. apiRequest() adds JSON headers and the bearer token from browser local storage.
  3. Vite forwards the request to Express. The route checks the Mongo connection and verifies the JWT.
  4. For profile writes, the server confirms every top-level field is allowed, merges those fields into that candidate’s profile, and saves the Mongoose document.
  5. The JSON response returns to the page; AuthContext updates its in-memory copy so the UI reflects the saved value.
Keep the responsibilities clear: React state is the immediate view state, not the durable database. MongoDB is the durable account data store. The JWT identifies who may access it. Groq generates suggestions but does not store a candidate profile.

Authentication lifecycle

  1. Register: POST /api/auth/register sends display name, email, password. The server validates, normalizes email, hashes the password with bcrypt cost 12, inserts a Candidate, and returns a JWT and profile.
  2. Restore: on app load, AuthProvider reads skillquest.session and calls /api/auth/me. The server verifies the token and returns the matching user and profile.
  3. Use the app: ProtectedDashboard renders the dashboard only when the context has a user; otherwise it redirects to /auth.
  4. Save: saveProfile() sends a PATCH with a partial profile; the API uses the candidate id in the verified token, not a client-supplied account id.
  5. Sign out: the client removes the token and clears user/profile memory. MongoDB data remains attached to the account for the next sign-in.

Candidate document

Mongoose model Candidate maps to MongoDB collection candidates in database skillquest. The schema has timestamps, a unique lowercased email index, and a password hash configured with select: false.

{
  _id: ObjectId,
  displayName: String,
  email: String,                 // unique, lowercase, trimmed
  passwordHash: String,          // bcrypt; excluded from normal reads
  profile: {                     // candidate-owned feature data
    resumeText, careerAnalysis,
    roadmapData, roadmapRequest,
    mindmap, selectedRole, skillLevels,
    learningProgress, interviews,
    jobPreferences, mentorRequests
  },
  createdAt: Date,
  updatedAt: Date
}
Profile fieldWhat it persists
resumeTextExtracted or pasted text; the binary upload itself is not stored.
careerAnalysisGroq summary, ATS score/breakdown, skills, paths, keywords, strengths, improvements, rewrite suggestions.
roadmapData / roadmapRequestGenerated output plus domain, learning goal, and daily hours input.
mindmapDomain/goal and raw node/edge graph so the visualization can be rebuilt after login.
selectedRole / skillLevelsTarget role and per-skill current/target percentages.
learningProgressCompletion booleans keyed by roadmap item title.
interviewsSession id/type/role/focus/date, generated questions, candidate answers, evaluations, final score, completion state.
jobPreferencesSelected domain and company filter query. There is no live job-feed record.
mentorRequestsMentor names for which the candidate saved a connection request.

The profile is a MongoDB Mixed object. The API limits updates to an explicit top-level allow-list and shallow-merges allowed properties. That keeps account ownership enforced, but does not deeply validate every nested value; a production evolution could replace Mixed with typed sub-schemas and request validation.

5. Groq AI Integration

AI generation is centralized in server/index.js. The frontend never calls Groq directly. Every /api/ai/* route first passes the database and JWT middleware, validates required inputs, builds a system/user prompt, calls the shared groqJson() helper, and returns structured JSON.

Model and JSON handling

  1. Read GROQ_API_KEY from the Node server’s environment. If absent, return a clear 503 instead of silently fabricating AI output.
  2. Fetch the available Groq models once and cache a preferred available model; fall back to llama-3.3-70b-versatile if model discovery cannot choose one.
  3. Send an OpenAI-compatible /chat/completions request with system/user messages, temperature, token limit, and JSON response format.
  4. If a model rejects the JSON response-format option with HTTP 400, retry without it.
  5. Parse plain JSON or a fenced JSON object, then validate key shapes for mindmaps/questions and apply safe defaults for resume analysis.

6. Frontend Features: Code Walkthrough

Home — src/pages/Home.tsx

Public entry page with navigation, feature summaries, and a roadmap form. Domain, learning goal, and available daily hours go to /api/ai/generate-roadmap. The generated response and original request are saved in the signed-in profile. A visitor can browse the page, but generation redirects to account sign-in.

Career Mapping — src/pages/CareerMapping.tsx

Accepts TXT, PDF, and DOCX files or pasted text. PDF extraction uses PDF.js in the browser; DOCX extraction uses Mammoth. Extracted text is trimmed and limited to 15,000 characters, then saved. The analysis request is authenticated and its JSON result is saved for reload. The result view displays ATS score/breakdown, keywords, rewrite suggestions, experience level, skills, strengths, improvements, and suggested career tracks. The original DOC format is explicitly unsupported.

Skill Roadmap — src/pages/SkillRoadmap.tsx

Two tabs: Interactive Mindmap and Skill Assessment. Eight predefined technical roles provide baseline skill targets. Candidate current proficiency is editable by sliders; releasing a slider persists the changed role-specific array. Learning item completion is stored in learningProgress. Links/resources are a bundled catalog, not AI-generated database records.

Mindmap — src/components/MindmapGenerator.tsx

Prompts for domain and goal; POSTs to Groq through the API; maps saved graph data into React Flow Node and Edge objects. Node color/spacing is based on hierarchy level. Raw graph plus inputs are saved, then reconstructed when the component mounts. The current Download icon displays an informational toast; actual image/PDF export is not implemented.

AI Interview — src/pages/AIInterview.tsx

Flow is select type → setup role/focus → generate questions → answer/evaluate → completion. A UUID identifies a session. Each evaluated answer and the updated question/answer arrays are persisted. Incomplete sessions can be restored from profile state; completed sessions appear in history with average score. HR/technical prompt focus controls the type of Groq questions.

Job Matching — src/pages/JobMatching.tsx

Stores selected domain and company filter in the profile. It filters a curated in-code list of company career pages and links to external job boards. It does not query a job API, scrape live listings, submit applications, or calculate a candidate/job match score. The screen says so rather than presenting mock matches as real.

Mentor Connect — src/pages/MentorConnect.tsx

Shows a sample mentor catalog, external developer communities, and links to GitHub “good first issue” searches. Clicking a mentor request stores the mentor name on the candidate profile and disables that request button. Community membership and mentor availability are not verified by this app.

Dashboard — src/pages/Dashboard.tsx and DashboardHome.tsx

Shared shell combines sidebar, nested route outlet, candidate display name, and sign-out. Dashboard home quick actions link to the feature pages. Progress is calculated from profile completion, saved skill values, and completed interview scores, not fixed percentages.

11. Security and Design Boundaries

BoundaryCurrent implementationInterview explanation / next improvement
Passwordbcrypt hash with cost 12; password hash excluded by default in Mongoose.Never store or return plaintext passwords. Add reset and verification flows for production.
SessionJWT signed with server secret, subject is Mongo user id, expires in 7 days; browser stores it in localStorage.localStorage is simple but exposed to successful XSS. Production could use secure HttpOnly SameSite cookies, refresh/revocation strategy, and CSP.
AuthorizationEvery profile/AI route verifies bearer token and queries by its sub.Do not accept a candidate id from the request body as authority. Add tests for cross-account access.
SecretsGroq key and JWT secret are server environment variables; .env ignored.Rotate keys if exposed; use a secrets manager outside local dev.
ValidationRegister and select API fields have manual validation; request JSON limited to 1MB.Use a schema validator such as Zod on the server, nested profile schemas, rate limiting, and consistent errors.
ResumeFile text is extracted in the browser, clipped to 15k characters, text saved in Mongo and sent to Groq.Resume content is personally identifiable data. Add explicit retention/deletion controls, encryption/storage policy, and consent.
Job/mentor contentCompany links, community URLs, and mentor examples are static UI data.They are not live verification, job ranking, application tracking, or real mentor availability.
Mongo profileMixed schema with allow-listed top-level fields.Typed subdocuments and field-level limits avoid malformed/oversized nested data.

Important vocabulary

JWT signed claims used as a bearer session token. Mongoose Node object/document mapper for MongoDB. Middleware Express function that runs before the route handler. Allow-list fields the API explicitly permits a profile update to change. Proxy Vite forwards a browser path to a separate backend during local development. JSON mode model request option encouraging parseable structured output.

12. Interview Practice

Answer with a clear sequence: problem → design decision → data/request flow → trade-off. Tie each explanation to a real file or endpoint.

Q1. Walk me through the architecture.

React/TypeScript pages are served by Vite. The browser calls relative /api endpoints; Vite proxies them to Express. Express validates and authenticates requests, reads/writes Mongo through Mongoose, and calls Groq for AI routes. Groq and Mongo credentials stay on the server.

Q2. How does a candidate’s profile remain private and load after login?

Login returns a JWT whose subject is the Mongo candidate id. The client stores the token and sends it as a bearer header. Middleware verifies it; profile routes query only req.candidateId. On reload, the auth provider calls /api/auth/me and hydrates the saved profile. Sign-out deletes client session state but not the database record.

Q3. How are passwords handled?

The server hashes at registration with bcrypt cost 12. The password hash is excluded in ordinary Mongoose selects. At login, bcrypt compares the supplied password with the stored hash. A JWT is returned only after successful comparison.

Q4. Why not call Groq from the React app?

A browser bundle is public, so any embedded API key can be copied and abused. The frontend calls an authenticated local API; only the Express process attaches the Groq authorization header.

Q5. What happens if MongoDB is down?

Startup attempts to connect with a short selection timeout and exits if it cannot connect. Routes also check Mongoose connection state and return 503 when the database is unavailable. The health endpoint is the quick operational check.

Q6. What does the API do with model output?

It asks for JSON, retries without the response-format option for models that reject it, parses fenced or plain JSON, and checks required arrays for mindmaps and interview questions. Resume analysis gets safe defaults for missing fields.

Q7. What gets stored for a resume upload?

The browser extracts selectable text from TXT/PDF/DOCX, truncates it at 15k characters, then persists that text and the generated analysis in the candidate profile. The uploaded binary is not sent to Mongo.

Q8. Does “Job Matching” currently match actual jobs?

No live job source is connected. It stores the user’s domain/filter and displays curated employer career pages and job boards. It does not claim fabricated fit scores or application counts.

Q9. How are interview attempts saved?

A session receives a UUID and stores role/type/focus/date, questions, answers, evaluation feedback, completion state, and final average. The session is updated after each evaluated answer so progress survives a logout or reload.

Q10. What are the most important production improvements?

Use secure HttpOnly cookies or stronger token lifecycle controls, add rate limits and schema validation, add automated API/auth/data-isolation tests, model profile fields with typed subdocuments, build resume deletion/retention controls, and connect a real job feed before advertising matching results.

Q11. How would you add a new candidate profile field?

Define its TypeScript interface in src/lib/api.ts, add it to the server profile allow-list, persist/load it through saveProfile(), and write a focused test proving it saves for one account and cannot cross account boundaries.

Q12. Why use an Express API instead of connecting React directly to MongoDB?

Database credentials and authorization logic cannot safely live in a browser. The API is the trust boundary: it controls secrets, validates inputs, verifies identity, and scopes queries to the authenticated candidate.
